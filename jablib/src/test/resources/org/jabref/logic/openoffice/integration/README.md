# Writer safety-gate fixtures

Run `./gradlew :jablib:libreOfficeTest` from the repository root with real LibreOffice Writer and Pandoc installed.
Set `LIBREOFFICE_EXECUTABLE` and `PANDOC_EXECUTABLE` to executable paths when necessary.
Neither dependency is mocked, and an unavailable executable fails the task rather than skipping tests.
When running the whole OpenOffice unit-test group, also put the Pandoc directory on the process-local `PATH`: the older `BstPipelineTest` invokes `pandoc` by name rather than reading `PANDOC_EXECUTABLE`.
For architecture orientation, see [JabRef on DeepWiki](https://deepwiki.com/JabRef/jabref).

## Golden documents

These minimal, hand-authored flat OpenDocument files are independent input oracles, not output regenerated by the code under test.
They contain fixed mark names and text, with no generated timestamps, random identifiers, or version-specific Writer serialization.
The tests open them in Writer, assert explicit names/text and container contents, save as `.odt`, reopen, and assert again.
Assertions compare semantic document contents rather than ZIP bytes or Writer-generated XML formatting.

| Fixture | Format | Contents |
| --- | --- | --- |
| `canonical.fodt` | `JABREF_<key>[, JABREF_<key2> ...] <TYPE> <uid>` | Body, footnote, table, and empty citations with explicit `U+200B` boundaries and a 12 pt paragraph default |
| `jstyle.fodt` | Legacy `JR_cite*` | Body, footnote, table, invisible citation, page-info property |
| `csl.fodt` | Legacy `JABREF_* CID_n` | Superscript body, footnote, and table citations |
| `csl-empty.fodt` | Legacy `JABREF_* CID_n ... EMPTY` | Zero-length citation between surrounding words |
| `bst.fodt` | Legacy `JABREF_* CID_n` | Numeric body, footnote, and table citations |

The legacy fixtures are retained deliberately: Writer must preserve them on save/reopen, but the canonical engine must ignore them rather than silently read or migrate them.
Canonical assertions check both boundary characters explicitly before inspecting the inner text; they do not remove arbitrary invisible characters to hide a mismatch.
`superscript.csl` is a small local numeric CSL style with superscript citations and a title-only bibliography.
It exercises the same superscript rendering behavior used by Nature and AMA without coupling expected text to upstream style changes.
`golden.bst` emits title-only bibliography entries, allowing the BST VM → real Pandoc → Writer path to have deterministic expected text.
`zotero-native.json` is native Zotero citation data without a JabRef URI; tests attach it to a real Writer mark.
`zotero-numeric.csl` provides deterministic bracketed citations and a numbered, title-only bibliography for Zotero-mode tests.

## Engine acceptance coverage

`WriterIntegrationTest` calls the public `CitationEngine` API and requires at least 28 test invocations:

- Refresh each family against the canonical golden document; assert body, footnote, table, empty marker, numbering, bibliography order, and exported keys after save/reopen.
- Insert all six citation types with page infos using JStyle, then switch JStyle → CSL → BST → JStyle, saving and reconnecting at each step.
  Names, types, key storage order, and every page-info property must survive; the final JStyle marker text must match the original exactly.
- Insert citations before existing citations for each numeric renderer and assert that both markers and bibliography follow the resulting document order.
- Reconnect and refresh superscript citations five times to defeat the writer's unchanged-text cache.
  Capture each citation's initial `CharHeight` before any rendering and require that same height after every refresh and save/reopen.
  Writer's footnote style can use 10 pt even when body/table text uses 12 pt, so a single document-wide height would be incorrect.
  Also require `CharEscapementHeight = 58`, `CharEscapement = 33`, and normal surrounding text.
- Use a nonexistent Pandoc path for both insertion and refresh.
  Require an error and an unchanged snapshot of body text, footnotes, tables, marks, formatting, user properties, bibliography, redline count, recording state, and controller locks.
- Prove that all four legacy fixtures are ignored by refresh and export without losing their stored content or properties.
- Merge and separate adjacent JStyle citations through the engine, retaining each citation's page info and key order across refresh and save/reopen.
- Enforce CSL/BST group-edit capability restrictions without document mutation.
- Preserve a genuine user redline while refreshing and restore change recording and controller locks.
  Also exercise the exceptional path of the recording-suspension helper.
- Close and reopen the library scope: unresolved keys must become visible placeholders, stay exportable as unresolved keys, and recover without changing canonical identity.

A test being present is not evidence of a passing implementation: require a green run of the completed engine.
These tests do not replace the pure renderer/parity tests or the separate 300-citation performance gate.

## Zotero acceptance coverage

`ZoteroWriterTest` requires at least 25 real-Writer invocations through the public linker and `CitationEngine` in Zotero-compatible mode:

- A unique native duplicate gains a JabRef URI without losing the native URI, JSON metadata, mark text, or citation identity; later insertion reuses that native URI.
- Ambiguous duplicate candidates remain unlinked and export as unresolved rather than selecting an arbitrary library entry.
- Normal, in-text, and empty marks remain independent through refresh, fresh engine connections, export, and save/reopen; empty marks stay invisible and included in the bibliography.
- Zotero-mode refresh leaves canonical and legacy CID/JStyle marks, `JR_bib`, and JabRef-specific document properties untouched.
- Non-CSL styles, unsupported partial citation types, page info, and group edits are rejected without changing document contents.

The tests parse the stored Zotero JSON to assert URI arrays, suppress-author flags, metadata, and stable names instead of treating successful rendering alone as sufficient.

## Entity contract coverage

`OOTextWriterTest` requires at least six real-Writer invocations and preserves the same assertions after save/reopen:

- Decoding `<b>M&uuml;ller &amp; &lt;i&gt;literal&lt;/i&gt;</b>` produces `Müller & <i>literal</i>`, with bold formatting but no italic formatting.
- Trailing text after the last formatting tag is decoded exactly once; escaped literal tags are never tokenized again.
- CSL and BST bibliography headings preserve literal ampersands, HTML-looking text, and entity-looking text without introducing character formatting.
- BST author-year citations and CSL numeric in-text prefixes display accented authors and ampersands rather than their HTML encodings.

## Storage regression gate

The same `libreOfficeTest` task requires at least 20 invocations from `CanonicalStorageWriterTest`, including undo/redo, page-info restoration, and transactional group-rendering failures.
The workflow separately runs every OpenOffice unit test using `:jablib:test --tests 'org.jabref.logic.openoffice.*'`.
It also requires reports for `MarkStoreTest`, `MarkWriterTest`, `PageInfoPropertiesTest`, `CanonicalReferenceMarkTest`, and the real-Pandoc `BstPipelineTest` individually.
Every OpenOffice unit report is checked for skips, errors, and failures, not only these named suites.
These are separate required reports, so discovering unrelated tagged tests cannot mask a missing engine, entity-contract, or storage suite.

## Isolation and CI enforcement

The harness starts Writer with a unique temporary profile and a dynamically selected loopback-only UNO port, disables document macros, and closes documents and its owned process after execution.
The dedicated task runs serially and cannot reuse cached results.
Startup, JUnit execution, and the Gradle task have bounded timeouts.
JUnit uses `@TempDir` for the profile and intermediate save/reopen files.
Documents and the process log for engine acceptance tests are saved under `jablib/build/writer-integration/engine-acceptance`; storage tests use a separate directory.
CI uploads those artifacts together with JUnit reports even on failure.

The workflow runs on every pull request and merge-group event, with no path filters, opt-in labels, or allowed failures.
It requires at least 28 engine, 25 Zotero, 20 canonical storage, and six entity-contract invocations, plus the five named unit suites, with no skips, errors, or failures.
The counts are minimums, not upper limits, so adding tests does not require weakening the report guard.
Repository administrators must make **Required Writer integration** a required branch-protection check; YAML alone cannot enforce that setting.

## Reviewing or changing a fixture

1. Open the `.fodt` in Writer, or inspect its XML, and confirm the intended mark names, boundary characters, and text containers.
2. Make a minimal semantic edit to the hand-authored XML; do not replace it with a full Writer-generated export.
3. Update explicit expected contents only when the intended behavior actually changes.
4. Run the dedicated task and inspect both the JUnit report and saved `.odt` artifacts.
5. Keep legacy fixtures as rejection/persistence oracles, not as migration inputs.
